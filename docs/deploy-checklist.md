# Post-deploy verification checklist

Moved out of the README, which had accumulated every check ever written.
Tick as you confirm on the live site; delete rows once they have been
through a full cycle. Newest first.

- [ ] **3.17.0 REINDEX REQUIRED (both collections)**: content bumps to `iwac_v8` (`author_entity_ids`, `publisher_entity_ids`) and the entity index to `iwac_index_v4` (`authored_count`). Until the rebuild, entity mention counts stay wrong in the way this release fixes — the new fields do not exist, so nothing changes on the old collections.
- [ ] **3.17.0 an author is no longer a stranger to the archive**: search `Wanlé Gérard Coulibaly` on `/search/everything`. The **PEOPLE** card must read **8 mentions · dont 8 signés** (EN: "8 as author"), not the `0 mentions` it showed while sitting directly above his own four articles. Cross-check against Hugging Face / the IWAC MCP: `frequency` there has always been 8, and the two figures must now agree. Same class of fix for ~3,045 entities.
- [ ] **3.17.0 newspapers and channels get real figures**: open the entity index and find **Sidwaya** and a YouTube channel (RTB, CERFI). Both must show a non-zero mention count — they read 0 before, because only subject/spatial headings counted. A publisher must NOT show a "signés" line: it publishes, it does not write.
- [ ] **3.17.0 the curator did not author the collection**: check Frédérick Madore's entity card. His `dcterms:contributor` link is on every article and is deliberately excluded from authorship — his "signés" figure must be in the dozens (his real `dcterms:creator` bylines), NOT ~12,000. If it is five figures, `dcterms:contributor` leaked into `author_entity_ids`.
- [ ] **3.17.0 multi-role entities are not double-counted**: pick a person who is both written about and a bylined author. Their mention count must equal the number of DISTINCT documents, not mentions+bylines — one item counts once however many roles it plays. Compare against the HF `index` row for the same person; they must match.
- [ ] **3.17.0 sort by most authored**: the entity index sort menu gains "Plus signé / Most authored" (`authored_count:desc`). It must rank the prolific journalists (Coulibaly Zoumana ~133, Thibaud C. Nagnonhou ~76) at the top, and entities that signed nothing at the bottom.
- [ ] **3.12.0 REINDEX REQUIRED**: the content collection bumps to `iwac_v7` for the audiovisual fields (`channel_ss`, `media_kind_s`, `media_platform_s`, `duration_seconds`, `rights_s`). Until the rebuild those facets do not exist, and — because audiovisual now routes `dcterms:publisher` to `channel_ss` — the videos keep showing their channel under "Journal" on the OLD collection. One rebuild covers this and the pending 3.11.0 sentiment bump.
- [ ] **3.12.0 the channel is not a newspaper**: after the reindex, open the new **Audiovisual (radio, TV, YouTube)** scope (or `/search?f.type_s=audiovisual`). Cards must show the channel with a camera icon, the running time in the dateline (e.g. `5:32`), and a "Voir sur YouTube / Watch on YouTube" link that is SEPARATE from the title link — the title must still open the IWAC item. No card may label a channel "Journal".
- [ ] **3.12.0 the Burkina Faso scope carries the videos**: `/browse/burkina-faso` (→ `/search?f.country_ss=Bénin`-style redirect) must show the ~1,099 YouTube records alongside the press, with a working **Chaîne / Producteur** facet (RTB, CERFI, L'Autregard, Burkina Info) and a **Format / Plateforme** facet separating YouTube from DVD/CD. Ticking `Type = Audiovisuel` then a channel must narrow correctly. Nigeria must not regress: `/browse/nigeria` still shows its ~45 deposited recordings, now with `DVD`/`CD` as their platform.
- [ ] **3.12.0 no empty IIIF links on YouTube items**: pick a template-23 video and confirm the result card shows its poster-frame thumbnail; the indexed document must carry NO `iiif_manifest` (its Omeka manifest has zero canvases). A deposited DVD must still carry one.
- [ ] **3.12.0 transcripts became searchable**: find a deposited recording whose Omeka item has `bibo:content` (e.g. item 15850) and search a phrase from that transcript. It must now match with a highlighted snippet — the subset never read `bibo:content` before this release — and show under the "Full text available" filter.
- [ ] **3.11.0 REINDEX REQUIRED**: the sentiment fields move to the generation-2 annotators — `gpt_5_6_luna_*`, `mistral_small_2603_*`, `deepseek_v4_flash_0731_*` — and the generation-1 trio (`gemini_3_flash_preview_*`, `gpt_5_mini_*`, `ministral_14b_2512_*`) is gone. The content collection bumps to `iwac_v6`; new field names cannot happen in place, so **the sentiment facets stay empty until the rebuild**. After it: the Sentiment group on `/search` shows Polarité / Centralité / Subjectivité with counts again, now from GPT-5.6 Luna. Spot-check one article against Omeka — the facet value must equal its `iwac:gpt56Luna*` value, NOT its `iwac:gemini*` one.
- [ ] **3.11.0 retired sentiment names are dropped, not remapped**: open a pre-3.11.0 share link, e.g. `/search?f.gemini_3_flash_preview_polarite_ss=Neutre`. It must run UNFILTERED (no sentiment filter applied, no error) — deliberately, since no generation-2 model is an honest stand-in for a generation-1 judgement. Same for a page block saved with the old facet names: it renders without its Sentiment facets, and re-picking the new ones in the admin restores them.
- [ ] **3.10.0 block value pickers**: edit a page with an IWAC Search block. Below Scope there is a checkbox picker per field (Type, Country, Newspaper, Language, the three sentiment fields) with document counts. Set Scope to **All content**, tick Bénin + Togo and Type = news article, save. The public block must show only Béninese and Togolese articles; view-source the inlined bootstrap and confirm ``locked_filters`` reads ``type_s:=[`article`] && country_ss:=[`Bénin`,`Togo`]``. No reindex required.
- [ ] **3.10.0 pickers degrade**: stop Typesense (or point the alias at a missing collection) and reopen the same page-edit form. It must still render, with the Newspaper/Language/sentiment pickers replaced by the "index is unreachable" note and the already-ticked values preserved — not a 500. Re-save and confirm the block keeps its scope. Restart Typesense; the options return.
- [ ] **3.10.0 blocks saved before 3.10.0**: open an existing block (preset or custom) and confirm its results are unchanged before you touch anything — an absent `filter_values` must compile to nothing and leave the filter string byte-identical.
- [ ] **3.8.0 REINDEX REQUIRED**: the content collection bumps to `iwac_v5`. After the rebuild, search a title or topic that occurs only inside a publication issue's table of contents; the issue must appear with a highlighted ToC snippet. - [ ] **3.9.0 legacy search redirects**: `/s/westafrica/item/search?fulltext_search=Ghana` returns 302 to `/s/westafrica/search/everything?q=Ghana`; `/s/afrique_ouest/item/search?q=ramadan` returns 302 to `/s/afrique_ouest/recherche/tout?q=ramadan`. - [ ] **3.8.0 non-press bodies**: open a photograph and an audiovisual search result whose Omeka item has `dcterms:description` but no `bibo:shortDescription`; the card must show that description. Items with an AI summary must still prefer it.
- [ ] **3.8.0 export fidelity**: combine a text query, country/type facet and year range, change the sort, then export TXT, JSON, RIS and BibTeX. - [ ] **3.8.0 facet checkbox alignment**: on `/s/westafrica/page/benin` and another country page with a wrapping facet label, verify the checkbox square, label and count are vertically centered on desktop and in the mobile filter drawer.
- [ ] **3.7.1 reindex runs at all**: `OmekaSourceReader` bound its `IN (:ids)` lists with `Doctrine\DBAL\ArrayParameterType`, which only exists from DBAL 3.6 — Omeka S 4.x pins `doctrine/dbal ^2.13.8`, so every reindex died at the first value query with `Class "Doctrine\DBAL\ArrayParameterType" not found`. Now bound with the legacy `Connection::PARAM_INT_ARRAY` / `PARAM_STR_ARRAY` (identical ints, portable to DBAL 3.x). Confirm the bulk reindex reaches the alias swap instead of failing in `EntityAuthority->build()`.
- [ ] **3.6.2 REINDEX REQUIRED**: audiovisual now derives `country_ss` from its place heading (`dcterms:spatial` → `IwacInstance::COUNTRY_PLACE_NAMES`), so the recordings only gain a country on rebuild. - [ ] **3.6.2 mobile toolbar**: on a phone (~450px wide), open a country page **with results**.
